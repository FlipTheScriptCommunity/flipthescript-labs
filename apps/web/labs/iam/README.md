# IAM lab — source

React + Cloudscape source for the interactive "Create user" lab embedded at
`/courses/aws-foundations/labs/iam`. See `apps/web/labs/README.md` for how
labs are built, embedded and added.

## Why isolated / embedded via iframe

See `apps/web/labs/ec2/README.md` — same reasoning (RTL Hebrew dark theme
vs. the real, light/LTR Cloudscape AWS console look), same `<iframe>`
embedding.

## Rebuilding

```sh
cd apps/web/labs/iam
bun install
bun run build
```

This bundles `client/index.jsx` with Bun's native bundler and writes
`bundle.js` + `bundle.css` into `apps/web/public/labs/iam/`, next to the
committed `index.html` shell.

## What's simulated vs. real

Everything here is a teaching mock:

- The account (`123456789012`), the existing users (`admin`,
  `ci-deployer`) and the user groups (`Admins`, `Developers`, `ReadOnly`)
  are static data in `client/data.js`.
- The managed policies are real AWS managed policy names, with simplified
  statements: enough to give the same allow/deny answer as the real policy
  for every action the simulator offers, not the full real documents.
- "Create user" doesn't call any backend. `client/mockCreateUser.js`
  validates the user name and custom password with the real console's
  rules, generates a password and fake ids, and — like the real console —
  attaches `IAMUserChangePassword` when the user must reset their password.
- `client/policyEval.js` is a small version of IAM's policy evaluation:
  an action is allowed only if an attached policy (directly or through a
  group) has a matching Allow statement; otherwise it's an implicit deny.
  None of the policies use Deny statements.

## How this lab differs from EC2/S3/VPC

The real IAM console creates users with a three-step wizard, so this lab
uses Cloudscape's `Wizard` instead of a single long form with a sticky
summary panel. The guided walkthrough is split the same way: one short
walkthrough per screen (`details`, `permissions`, `review`, `user` in
`client/tutorialSteps.js`), each opening the first time its screen is
shown. Screens in the middle of the wizard have no `welcome`, so
`TutorialOverlay` skips the popup and goes straight to the spotlight.

## Flow

1. **Specify user details** — user name, optional console access with an
   autogenerated or custom password, and "must create a new password at
   next sign-in".
2. **Set permissions** — add the user to groups, copy an existing user's
   permissions, or attach managed policies directly.
3. **Review and create** — summary of the user and their permissions,
   plus optional tags.
4. **User page** — console sign-in details (password shown once), summary
   with the ARN, effective permissions (add / remove policies), group
   memberships, and a policy simulator that checks which actions the user
   is allowed to perform.
